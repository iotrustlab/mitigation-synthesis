# Procedure-study experiments

This directory contains the formal-side experiments discussed with the three
SPHERE procedure use cases. The case controllers, scenarios, saved run bundles,
plant checks, path/cost calculations, and generic CHP surrogate are in
[`iotrustlab/sphere-usecases/experiments/procedure_study`](https://github.com/iotrustlab/sphere-usecases/tree/codex/procedure-usecases/experiments/procedure_study).
The research framing and formal inputs/outputs are in
[`FORMAL_FRAMEWORK.md`](FORMAL_FRAMEWORK.md). The HTML presentation is deliberately
not part of either repository.

## What is established

| Experiment | Input | Output and claim |
| --- | --- | --- |
| [Attleboro authority proof](../attleboro/README.md) | Source-mapped, manual one-scan hybrid-program abstraction | Two KeYmaera X safety proofs plus reachable witnesses; generator operation or restored utility without a new reset keeps remote PLC actuation ineligible after that scan. |
| [CLEO guarded choice](cleo/attleboro_documented_choice.envelope) | Proposed Remote-or-Hand command-location game with an already-eligible branch | `VERIFIED` for eligible command location. It does not synthesize an optimal response or establish water delivery. |
| [CLEO flow phase](cleo/attleboro_sampled_flow.envelope) | Authored pre-clamp finite ODE phase for the research simulator's 0.1-second flow update | `VERIFIED` for `0 <= q <= 10 L/s` after one phase. It is not a site hydraulic or end-to-end service theorem. |
| [ModelPlex controller monitor](modelplex/MODELPLEX_RECEIPT.md) | Two single-entry copies of the Attleboro authority game | Generated controller transition formulas. The local evaluator matches 25 applicable scans in each of two saved traces and rejects three output mutations; it does not monitor physical delivery. |

The [HyPLC subset probe](cleo/attleboro_hyplc_subset.st) drops located
declarations, retained initialization, and the timer so that its syntax is
closer to the available translator grammar. It is **not** the controller used
in SPHERE, and no full ST-to-hybrid-program translation or refinement proof
is claimed. Merwin and CHP have runnable evidence and abstraction maps in the
SPHERE branch, but no KeYmaera X recovery proof in this package.

## Reproduce the formal checks

Run from the `mitigation-synthesis` repository root. Python 3.11+, Java,
`z3`, and the commands needed by [`scripts/bootstrap_drics.sh`](../../scripts/bootstrap_drics.sh)
are required. The bootstrap downloads checksum-checked CLEO 0.1.0 and its
KeYmaera X 5.0 JAR into ignored `.external/cleo`; those dependencies are not
committed. On systems without `md5sum`, install the corresponding coreutils
command before bootstrapping.

```bash
scripts/bootstrap_drics.sh
mkdir -p .external/cleo/java-home
export JAVA_TOOL_OPTIONS="-Duser.home=$(pwd)/.external/cleo/java-home"
export CLEO_KEYMAERAX_TIMEOUT_SECONDS=300
.external/cleo/.venv/bin/python recovery_experiment/procedure_study/cleo/verify_choice.py \
  --output /tmp/attleboro_choice_verification.json
.external/cleo/.venv/bin/python recovery_experiment/procedure_study/cleo/verify_flow.py \
  --output /tmp/attleboro_flow_verification.json
```

The two checked-in JSON receipts in `cleo/` record the prior verified run.
The verification scripts print their result and can write to an explicit path;
they do not modify the repository by default. Compare `source_sha256` and
obligation status when rerunning. For the separate, stronger one-scan
KeYmaera X theorem and trace correspondence, use the commands in the
[Attleboro proof README](../attleboro/README.md) and the top-level
[`PROCEDURE_EXPERIMENT_RECEIPT.md`](../../PROCEDURE_EXPERIMENT_RECEIPT.md).

## Reproduce the ModelPlex trace check

The committed `.kym` files were generated by the CLEO artifact's KeYmaera X
5.0 CLI. Their first `@evidence` comment was normalized to relative input and
output names for portability; the monitor formula was unchanged. The original
raw-file SHA-256 values and normalized-file SHA-256 values are both recorded in
[`modelplex/MODELPLEX_RECEIPT.md`](modelplex/MODELPLEX_RECEIPT.md).

The following command regenerates one controller formula in a disposable
location. Repeat it with `attleboro_restored_no_reset_single_entry.kyx` for the
second branch. KeYmaera X may insert the invoked paths in a comment, so compare
the formula after that comment rather than expecting byte-identical headers.

```bash
java -jar .external/cleo/source/cleo/keymaerax.jar -launch \
  -modelplex recovery_experiment/procedure_study/modelplex/attleboro_bad_power_single_entry.kyx \
  -monitor ctrl -out /tmp/attleboro_bad_power_ctrl.kym -tool z3 -timeout 60
```

Clone the SPHERE procedure-usecases branch alongside this repository, then
evaluate the committed formula against its saved synthetic traces:

```bash
SPHERE_DIR=/path/to/sphere-usecases
python3 recovery_experiment/procedure_study/modelplex/evaluate_trace_monitor.py \
  --trace "$SPHERE_DIR/sector-water/attleboro-interconnection/runs/local-reference/generator_absent/tags.csv" \
  --output /tmp/attleboro_monitor_result.json
python3 recovery_experiment/procedure_study/modelplex/evaluate_trace_monitor.py \
  --trace "$SPHERE_DIR/sector-water/attleboro-interconnection/runs/local-reference/adversarial_scada_compromised/tags.csv" \
  --output /tmp/attleboro_monitor_compromised_result.json
```

The default monitor checks the bad-power branch only. `startDemand` is
universally checked over both Boolean values; the unobserved prior-reset
memory is existentially projected. In the compromised trace, the PLC outputs
still match the monitor while 22 delivered-output rows differ downstream. The
Python evaluator is an offline trace checker; neither generated C code nor a
deployed runtime monitor is claimed.

The separate BYU public-exposure surrogate mentioned in the research framing
is contextual evidence-tagging work. Nothing in this package imports it or
requires it for a rerun, and no BYU dynamics are applied to the Polish CHP.
